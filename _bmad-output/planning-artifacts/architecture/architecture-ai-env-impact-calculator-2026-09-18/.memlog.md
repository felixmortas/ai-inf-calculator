- (constraint) Le calculateur est déployé comme un site statique autonome sous le chemin /ai-inf-calculator/ du dépôt GitHub Pages de felixmortas.com ; aucun serveur complémentaire.
- (constraint) Les conversations, les calculs et le catalogue de données restent entièrement dans le navigateur ; aucune clé API ni transmission de texte à un service externe.
- (constraint) L’interface est en français au lancement et les libellés doivent être internationalisables sans réécrire la logique de calcul.
- (decision) Le calculateur est un sous-projet portable dans le dossier ai-inf-calculator/ ; son dépôt de travail est distinct du dépôt hôte de felixmortas.com. Son contrat d’intégration est une sortie statique publiée au chemin /ai-inf-calculator/, sans dépendance au framework du site hôte.
- (direction) Le dépôt hôte devra adopter un build GitHub Actions ou un mécanisme équivalent qui inclut les fichiers compilés de ai-inf-calculator au chemin /ai-inf-calculator/ ; le choix du workflow précis est différé à l’intégration.
- (decision) Le sous-projet ai-inf-calculator/ utilise React, TypeScript et Vite. Il est une application monopage sans routeur ; React possède le rendu et un reducer local possède l’état éditable de la conversation. Le noyau de calcul reste des modules TypeScript purs, indépendants de React.
- (decision) La tokenisation est fournie par un adaptateur local exécuté dans un Web Worker. Son implémentation primaire est js-tiktoken/lite avec les rangs o200k_base empaquetés au build, sans CDN ni requête réseau ; en cas d’échec, elle retourne l’estimation locale mots/0,75. Le worker est sans état persistant et l’interface ne reçoit que les comptes et erreurs structurées.
- (decision) Le pays utilisateur est une suggestion locale, non une géolocalisation mesurée : table embarquée fuseau IANA vers pays probable, puis région de la locale du navigateur, puis Monde. Aucune requête IP, API de géocodage ou géolocalisation GPS n’est autorisée. Le pays proposé est toujours visible et modifiable avant le calcul de l’équivalence douche.
- (decision) Les données de référence sont des catalogues locaux versionnés avec l’application, séparés par domaine et accompagnés de métadonnées de provenance et calibration. Elles sont validées au build et ne sont jamais téléchargées à l’exécution. Les réglages avancés sont des surcharges de session en mémoire, jamais une mutation du catalogue.
- (decision) Chaque résultat de bloc porte une empreinte déterministe des textes pertinents, du modèle, des paramètres résolus, des données de référence et de l’algorithme. Après toute mutation, l’état dérive sa fraîcheur en comparant cette empreinte ; un total ne peut agréger que des résultats actuels.
- (decision) Les contenus utilisateur et résultats vivent uniquement dans le reducer React en mémoire. localStorage, IndexedDB, cookies applicatifs, analytics et journalisation distante sont interdits. Fermer ou recharger la page remet la session à zéro.
- (decision) L’internationalisation utilise des catalogues de messages typés indexés par clé, avec fr-FR comme unique locale livrée et les API Intl pour le formatage. Les formules, unités de stockage et données numériques n’incorporent aucun texte traduit.
- (decision) La fraîcheur distingue impactFingerprint et showerFingerprint : le premier couvre les données et paramètres d’impact ; le second couvre impactFingerprint plus pays utilisateur et paramètres douche. Une modification de douche n’invalide pas les impacts et le total peut réutiliser les impacts actuels pour actualiser sa seule équivalence.
- (decision) Le domaine fournit l’unique résolution canonique des paramètres : normaliser les clés, résoudre les facteurs de catalogue pays puis Monde, appliquer ensuite une surcharge de session autorisée, ou retourner indisponible. Une donnée indispensable absente sans repli ni surcharge valide bloque le résultat dépendant avec une erreur explicite ; le repli Monde reste signalé.
- (decision) Chaque demande Worker porte requestId et tokenizationFingerprint du texte et encodage ; le reducer ne consomme une réponse que si elle correspond encore à la demande en attente du bloc. Un calcul est indisponible tant que ses comptes requis sont pending ; les réponses tardives sont ignorées.
